## Safe replacement and restoration

1. Pause hourly UTC `0 * * * *` and wait for active loaders to finish. Preserve restart policy `NEVER` and native `python pipeline.py`; do not add HTTP health checks or persistent Start Command overrides. Back up the entire destination using `pg_dump --format=custom`, including warehouse tables, staging/schema metadata, and `_dlt_*` state. Preserve scoped roles/grants separately with operator-managed `pg_dumpall --globals-only`. Backups may contain credentials/data; keep them outside the repository.
2. Restore into a new isolated matching-major PostgreSQL instance and fresh volume. Restore/reconcile data, completed state, schema, and scoped roles together. Re-run counts/revenue/freshness and ingestion before touching production. The authenticated synthetic fixture is qualification only, never a default source or evidence about a real provider. Repeat historical local restore proof against final pins, then independently qualify Railway restoration and your API.
3. Keep `PIPELINE_NAME=rest_orders`, `DATASET_NAME=rest_warehouse`, resource `orders`, source `orders_api`, integer primary key `id`, and `updated_at` Unix-second cursor units stable. The wrapper grants only `rest_warehouse` and `rest_warehouse_staging`; schema changes require adapted initialization/grants and fresh qualification. Changing `SOURCE_INITIAL_CURSOR` alone does not reset completed state. Review resets/backfills separately.
4. Replace the loader with the exact reviewed source/image. Destination state restores before extraction; unfinished local packages do not survive scratch loss. Source records must remain replayable under inclusive `updated_since`, stable `page_number` pages starting at 1, `data`/`total_pages`, and integer `amount_cents`. Default `merge` keyed by `id` and 3600-second lookback can replay updates/inserts; they do not provide exactly-once, delete-aware CDC, arbitrary REST/provider compatibility, or HA. Hard deletes and older backdated changes need reconciliation/backfill. Crashed advisory-lock sessions release when disconnected.
5. Verify repeated loads, exact completed cursor restoration, interrupted replay, updated/new IDs, failed-source nonzero exit, and [sql/reconciliation.sql](sql/reconciliation.sql) before resuming cron. Observe an actual scheduler firing. Build success/database readiness alone does not prove ingestion success. Roll back an image only after checking schema/state compatibility; otherwise restore a reviewed whole-database backup.

Preserve two private repo-backed services, `dlt Loader` and the least-privilege `Postgres` wrapper, and no public domains/TCP proxies. The nonsuperuser `dlt_loader` must retain only its scoped grants. One Postgres-only 5000 MB mount at `/var/lib/postgresql/data` is the storage contract; never attach it to the loader or share it across services. A volume is persistence, not a backup. PostgreSQL major upgrades require verified dump/restore or a separate `pg_upgrade` plan, never an image swap under incompatible files.

## Credentials and release gates

`SOURCE_BASE_URL` and `SOURCE_API_TOKEN` remain required empty user inputs; every deployment needs an actual HTTPS API base URL and actual upstream read-only bearer token, never generated substitutes. Keep insecure HTTP restricted to local fixture qualification. Generate nonempty independent administrator and loader database secrets; initialized roles need authenticated SQL password changes before coordinated service-reference updates. Changing environment variables alone does not rotate role passwords. Keep administrator credentials out of the loader; rotate source tokens at the provider.

Run local checks and [PUBLISHING.md](PUBLISHING.md) gates before updating a release channel. A finite source-only permission/default review does not clear the assembled image or grant runtime security clearance. Recheck upstream notices and source obligations for final image contents.

Temporary qualification uses standard deletion plus verified zero compute and disclosed retention: stop/cancel work, verify zero running/transitional instances and zero queued work, delete owned temporary resources, and disclose retained logs/backups/storage. Physical storage deletion and billing-zero proof are not publication gates. See [README.md](README.md) and [SUPPORT.md](SUPPORT.md).
