# Publishing runbook

Template release **v1.0.1**; [VERSION](VERSION) is authoritative. A source release does not prove marketplace publication or live Railway qualification. This release must be qualified independently. These are operator instructions; completion requires evidence for the exact source and stored graph.

Release source selection is `tech-progress/dlt-rest-postgres`, branch `release-v1`, root `/`. Verify repository accessibility, GitHub App grants, the existing branch and immutable commit/tag before reuse. Historical local evidence for v1.0.0 (2026-10-02) includes authenticated synthetic orders, interrupted replay, denied privileges, failed-source exit, and full destination dump/restore. It does not establish current live qualification or observed hourly Railway scheduler firing.

## Source and local gates

1. Prepare a self-contained sanitized standalone tree. Include all public guides linked from [README.md](README.md), [LICENSE](LICENSE), and retained public [LICENSE_REVIEW.md](LICENSE_REVIEW.md). Exclude private evidence journals, local environment files, secret values, caches, and internal history. Preserve [dlt](https://github.com/dlt-hub/dlt) and [PostgreSQL](https://www.postgresql.org) links in every GitHub-facing README. Do not invent repository/release existence, marketplace IDs, or share codes.
2. Set `TEMPLATE_SOURCE_REPO=tech-progress/dlt-rest-postgres`, `TEMPLATE_SOURCE_BRANCH=release-v1`, and `TEMPLATE_SOURCE_ROOT_DIR=/`. Run `npm ci --ignore-scripts`, `node scripts/verify-docs.mjs`, `node --test tests/docs.test.mjs`, `./scripts/verify.sh`, `./scripts/build.sh`, and `./scripts/smoke.sh` on final pins. Optional verifier `--skip-version` and test environment `DLT_DOCS_SKIP_VERSION=1` defer only VERSION agreement during the owner's update; release validation must use the full version gate.
3. Confirm dlt `1.30.0`, locked dependencies, frozen installation, native loader `python pipeline.py`, and immutable base images. Read the PostgreSQL pin from [Dockerfile.postgres](Dockerfile.postgres) and loader construction from [Dockerfile](Dockerfile). A finite source-only permission/default review does not clear the assembled image. Complete the final image's dependency/license/notice inventory and applicable corresponding-source delivery before distribution; recipe MIT does not relicense upstream software or grant security clearance.

## Graph and live qualification gates

1. Compile/review [.railway/railway.ts](.railway/railway.ts). Require exactly two private repo-backed services, `dlt Loader` and the least-privilege `Postgres` wrapper, both on the selected repository/branch/root with their respective Dockerfiles. Require one Postgres-only 5000 MB mount at `/var/lib/postgresql/data`, no loader volume, no public domains/TCP proxies, and hourly UTC `0 * * * *`, one replica, restart policy `NEVER`. Clear stale Start Command/HTTP health-check overrides to preserve Docker `CMD`.
2. Require `SOURCE_BASE_URL` and `SOURCE_API_TOKEN` as required empty user inputs: actual HTTPS API base URL and actual upstream read-only bearer token supplied by the deployer, neither generated. Independently generate nonempty `POSTGRES_PASSWORD` and `DLT_LOADER_PASSWORD` secrets, preserving them across redeployments. The loader references only the latter and private database DNS. Verify `dlt_loader` is a nonsuperuser scoped to `rest_warehouse`/`rest_warehouse_staging`, with no database/role creation, replication, or public/unrelated-schema writes.
3. In an authorized source project, create or select an existing UNPUBLISHED draft using actual returned identifiers. Export Composer `serializedConfig` to an operator-controlled file. Run `scripts/restore-template-draft.sh EXPORTED.json > RESTORED.json`, then `scripts/audit-template.sh RESTORED.json` with the same explicit source settings. These offline transforms preserve existing IDs and require the right named services and one volume. They do not create a remote draft or prove live compliance.
4. Store the reviewed configuration, then inspect the queried stored graph. Confirm source coordinates, Dockerfiles, cron/restarts, private networking, mount, unresolved independent secret generators, required empty inputs/descriptions, and no resolved credentials. Validate the current Composer schema; a local compiled/restored graph cannot substitute for Railway's stored graph.
5. Deploy the stored draft into a disposable authorized project through the actual deploy flow (`templateDeployV2` when applicable). Supply a compatible authenticated source and capture returned IDs privately. The authenticated synthetic fixture is qualification only, never a default source or claim about a real provider. Live qualification must satisfy the actual HTTPS/auth contract with `ALLOW_INSECURE_SOURCE=false`.
6. Observe deployment/build SUCCESS and live workload state separately. Prove the exact orders contract from [README.md](README.md): `page_number` starting at 1, `data`/`total_pages`, inclusive `updated_since`, integer `id`, `updated_at` in Unix seconds, integer `amount_cents`, `merge`, and 3600-second default lookback. Verify first/no-change/update+insert loads, failed-source nonzero exit, interrupted loading/replacement after scratch loss, full destination backup/restore, least privilege, and reconciliation. Observe an actual hourly UTC scheduler firing and completed exit, private DNS, overlap/lock handling, and bounded resource soak. Build-only success or database readiness is insufficient. Record which API was tested; synthetic orders do not establish a real provider's behavior. Re-test independently with the deployer's API.

## Cleanup and marketplace gates

Stop schedules/active runs, cancel pending deployments/jobs, and re-query zero running/transitional instances and zero queued work. Delete only owned temporary projects/services/volumes/fixtures and verify resulting resource state. Disclose retained logs, backups, recoverable storage, and known provider retention intervals. Standard deletion plus verified zero compute and disclosed retention satisfies the owner's cleanup policy. Physical storage deletion and billing-zero proof are not publication gates under the accepted policy.

Once release-source, image, queried-graph, live workflow, and cleanup gates pass, register real source/template identifiers in the repository-wide marketplace registry. Use the dlt product icon and exact 45–75 character description from [MARKETPLACE.md](MARKETPLACE.md), with both main upstream links. From the maintenance repository run `scripts/sync-template-marketplace.sh dlt-rest-postgres`, then require `scripts/audit-template-marketplace.sh` to pass against live Railway/GitHub metadata before considering publication complete. These are maintenance tooling, not files assumed to exist in standalone distribution. Update public status only from observed evidence.
